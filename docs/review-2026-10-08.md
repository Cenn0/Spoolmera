# Security and product review — 2026-10-08

## Scope reviewed

Existing Angular/FastAPI inventory behavior, authentication and account administration, printer network boundaries, print-job import, automatic material consumption and Docker deployment.

## Findings and remediation

| Severity | Finding | Disposition |
| --- | --- | --- |
| High | Formerly unauthenticated inventory writes and readable label endpoints | Fixed: authenticated cookie sessions, CSRF-bound mutating requests, role checks, restricted first-admin bootstrap |
| High | Remote controller URL could become an SSRF primitive | Fixed: explicit RFC1918/ULA literal-IP allowlist, no DNS, public/loopback/link-local rejection, no proxies or redirects, bounded HTTP fetch |
| High | Duplicate completion events might double-subtract material | Fixed: unique job-linked movement IDs, terminal job states, identity checks and one SQLite write transaction |
| High | Ambiguous OctoPrint idle state could be mistaken for success | Fixed: OctoPrint jobs require deliberate review, no automatic debit |
| Medium | Initial rate-limit implementation rolled back denied login records | Fixed: invalid login attempts committed before raising HTTP errors |
| Medium | Password hashing could be hardened | Fixed: Argon2id with OWASP-aligned parameters; transitional legacy hashes rehashed at login |
| Medium | Printer API tokens at rest | Avoided: token values are configured only through private process environment, never persisted to SQLite |
| Medium | Frontend viewers could see mutation controls despite server-side denial | Fixed: controls gated by role, API remains authoritative |
| Medium | Password reset prompt displayed passwords unmasked | Fixed: inline password-type field |
| Medium | Container build context could include private configuration | Fixed: .env files excluded from Docker build; optional runtime env_file |
| Low | Legacy readme and integration documentation described unavailable features and broken code block escaping | Fixed: accurate capabilities, security and deployment docs |

## Verified behavior

The CI matrix validates Angular TypeScript/build, existing and new Python API regression tests, a real Chromium workflow (first-admin setup, inventory, QR, CSV, deep link and mobile layout) and Docker startup. Printer tests use mocked responses shaped after the documented Moonraker and OctoPrint HTTP APIs; they verify observed-running → completed job accounting and confirm no double debit.

## Remaining limitations and risks

- No actual Moonraker/OctoPrint device has been connected in this automated validation. Compatibility across firmware versions, printer authentication settings and failures requires hardware-in-the-loop testing.
- Printer polling is in-process. The application must remain single-worker; distributed deployments need an external scheduler and leases.
- G-code import covers a single estimated gram value, not multi-extruder tools, measured purge/waste, hardware spool identification or arbitrary slicer configuration.
- **Automatic slicing is intentionally not implemented**; the user chose the acceptable alternative of print-job metadata import.
- No native SSO, MFA or organization/tenant data isolation. Inventory is shared by all accounts with role permissions.
- Printer credentials remain visible to the container administrator through the process environment. Docker host compromise is outside the app's threat model.
- For security, prefer restricted LAN or VPN, trusted TLS reverse proxy, secure cookies and unique read-only printer API credentials. A code review and green CI do not constitute a penetration test.

## Support and recommendation classification

- **Works technically (tested):** role gates, session flows, print-job state machine and transaction guarantees under mocked controllers.
- **Officially documented API usage:** Moonraker's print history and status polling; OctoPrint's job/status endpoint. No hardware-version certification implied.
- **Best practice implemented:** OWASP-aligned Argon2id, unique salts, server-side sessions, CSRF checks, transactional idempotency, explicit network allowlist.
- **Security recommendation:** keep the service non-public or behind VPN/TLS with Secure cookies and use least-privilege printer tokens.
