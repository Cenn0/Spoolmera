# Filament Manager

> **Fully AI-developed, human-engineered — an AI software development experiment.**
>
> This project deliberately uses AI as its primary software developer. Implementation code and initial documentation are generated by AI; a human defines requirements, guides engineering decisions, evaluates the resulting software, and remains accountable for deployment and maintenance. The project is also an ongoing test of what an AI-led software engineering workflow can deliver, where it falls short, and how well its results can be verified and maintained.
>
> **Experimental software.** Automated tests establish only the behavior they cover. Neither AI generation nor a green CI pipeline guarantees production readiness, security, or absence of defects.

**Filament Manager** is a lightweight, self-hosted web application for managing 3D-printer filament products, physical spools, and remaining material.

[![License: Apache-2.0](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)

## Features

- Responsive dashboard for total stock, opened spools, low-stock warnings, and material distribution.
- Separate product catalogue (brand, material, color, diameter) and physical spool inventory.
- Per-spool starting weight, remaining weight, storage location, condition, and notes.
- Transactional consumption and adjustment records with a full, immutable movement history per spool.
- Archive spools without deleting their history.
- Stable UUIDs for products and spools, including automatic migration of existing databases.
- Printable **60 × 40 mm QR labels** for individual spools. QR codes open the matching spool in this app.
- **Versioned CSV export and import** with preview, validation, transaction rollback on errors, and idempotent UUID-based matching.
- **Read-only integration API v1** as a foundation for later printer or slicer adapters.

Not implemented: authentication, external printer connections, automatic slicing or print-job import, automatic filament consumption, and multi-user management.

## Quick start (Docker)

Requires Docker with Compose.

\`\`\`bash
git clone https://github.com/Cenn0/FilamentManager.git
cd FilamentManager
docker compose up -d --build
\`\`\`

Open **http://127.0.0.1:8765** on the machine hosting Docker.

The database is stored persistently in the Docker volume \`filament_data\`. To stop the app without removing its data:

\`\`\`bash
docker compose down
\`\`\`

Do **not** run \`docker compose down -v\` unless you intend to remove your saved inventory.

### Configure QR URLs for other devices

By default, QR codes contain \`http://127.0.0.1:8765/s/<spool-uuid>\`. This works only on the host itself: **127.0.0.1 on a phone is the phone, not your server**.

Set \`FILAMENT_PUBLIC_BASE_URL\` to an origin accessible from the device that scans the label, for example \`http://filament.home.example:8765\` or \`https://filament.example.com\`. It must be an HTTP(S) origin without credentials, path, query, or fragment.

Example on a trusted private LAN, after deliberately changing the Compose port binding and ensuring the network is protected:

\`\`\`yaml
environment:
  FILAMENT_PUBLIC_BASE_URL: "http://192.168.1.10:8765"
\`\`\`

**Security warning:** This MVP has no authentication. Do **not** expose it directly to the internet or to an untrusted network. For remote use, place it behind an authenticating TLS reverse proxy or a secured VPN, restrict network access, and configure the public URL accordingly. The default Compose configuration deliberately binds the port to localhost.

### Print QR labels

1. Add a filament product and create an individual spool.
2. Go to **Spools**, then select **QR label** on the corresponding row or **Print QR label** in its details.
3. Use the browser's print dialog and select a **60 × 40 mm** label (scale 100%, no headers or footers).

The QR code identifies the **physical spool**, not just the filament product. Its URL stays stable through weight changes. The label's printed remaining weight is a snapshot and does not update automatically: print a fresh label if that number matters.

### CSV export and import

Use **Spools → Export CSV** to download an Excel-friendly UTF-8 inventory snapshot. Use **Import CSV** to select a file, preview the changes, then confirm.

- The v1 format includes every product, including products without active spools; it includes only *active* spools.
- Product and spool UUIDs make imports idempotent. An already-known UUID is **skipped**, never overwritten; archived spools are not reactivated.
- The import is **create-only**, atomic, and limited to 2 MiB / 2,500 data rows. Invalid input leaves the database unchanged.
- CSV is **not a complete backup**: historical movements and archived spools are not exported. Keep proper SQLite backups.
- To migrate a current inventory to a fresh instance, export from the old installation and import to the new one. A new initial movement is created for each imported spool, recording its current remaining weight.
- CSV export protects user-entered spreadsheet cells beginning with formula-like characters while preserving round-trippability with this importer.

See [CSV schema and limits](docs/csv-format.md).

### Printer / slicer integration foundation

The application currently provides a versioned, read-only JSON contract:

- \`GET /api/integrations/v1/capabilities\` — feature flags.
- \`GET /api/integrations/v1/spools\` — spool UUIDs, material metadata, remaining grams, and conditions.

These endpoints are not authenticated independently. No printer or slicer connection is implemented, and no automated inventory writes are accepted. See [integration design and roadmap](docs/integrations.md) for intended adapter boundaries, event-idempotency rules, and security requirements.

## Local development

Python **3.12+**:

\`\`\`bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
uvicorn app.main:app --reload --host 127.0.0.1 --port 8765
\`\`\`

Run tests:

\`\`\`bash
python -m pytest -q
\`\`\`

API documentation: http://127.0.0.1:8765/docs.

Configuration:

| Variable | Default | Purpose |
| --- | --- | --- |
| \`FILAMENT_DB_PATH\` | \`.data/filaments.sqlite3\` | Persistent SQLite database path; Docker uses \`/data/filaments.sqlite3\` |
| \`FILAMENT_PUBLIC_BASE_URL\` | \`http://127.0.0.1:8765\` | Fixed base URL embedded in spool QR codes |

### Migrations and backups

The first startup of v0.2 adds UUIDs to existing products and spools in-place, keeping their numeric IDs and movement history. Before upgrading an existing installation, **take a consistent SQLite backup** (via SQLite backup API or a stopped container and its volume data). The migration is designed to be idempotent but does not replace a backup.

Back up the SQLite database and associated WAL content consistently, not by copying an open database file without a snapshot.

## Architecture

\`\`\`text
app/
  main.py            HTTP routes and inventory transactions
  database.py        SQLite schema, v2 migration, connection lifecycle
  models.py          Input validation
  inventory_csv.py   Safe inventory CSV import/export
  labels.py          QR payload and printable label generation
  integrations.py    Versioned read-only integration boundary
  static/
    index.html       Main user interface
    app.js           Frontend interactions
    styles.css       Application design
    label.css        60 × 40 mm label print rules
tests/               API and regression tests
docs/                CSV and future adapter contracts
Dockerfile
compose.yaml
.github/workflows/    CI and Docker smoke checks
LICENSE              Apache License, Version 2.0
\`\`\`

Balances are stored as whole grams, not floating-point quantities. Each consumption or adjustment and its corresponding ledger entry are committed in a single SQLite write transaction. The application has no CDN or external frontend dependencies.
