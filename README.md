# Spoolmera

<img src="frontend/public/spoolmera-wordmark.svg" alt="Spoolmera — Your 3D Printing Workspace" width="440">

**Your 3D Printing Workspace.** Manage filaments, printers and print jobs.

> **Fully AI-developed, human-engineered — an AI software development experiment.**
>
> This project deliberately uses AI as its primary software developer. Implementation code and initial documentation are generated by AI; a human defines requirements, guides engineering decisions, evaluates the resulting software, and remains accountable for deployment and maintenance. The project is also an ongoing test of what an AI-led software engineering workflow can deliver, where it falls short, and how well its results can be verified and maintained.
>
> **Experimental software.** Automated tests establish only the behavior they cover. Neither AI generation nor a green CI pipeline guarantees production readiness, security, or absence of defects.

**Spoolmera** is a **free, open-source, self-hosted** web application for managing 3D-printer filament products, physical spools, and remaining material. No subscription, hosted account, paid API or third-party cloud service is required. The code is licensed under Apache-2.0; third-party components keep their own licenses.

## Features

- **Angular 22 Material Workspace**: responsive dashboard, searchable spool inventory, product catalog, movement ledger and capability pages.
- **English and German interface**: instant language selection on sign-in and inside the app, saved browser preference, localized numbers/dates/prices and printable labels. Open forms retain their values when switching languages.
- Dashboard for total stock, opened spools, low-stock warnings, and material distribution.
- Separate product catalogue (brand, material, color, diameter) and physical spool inventory.
- Per-spool starting weight, remaining weight, storage location, condition, and notes.
- Transactional consumption and adjustment records with a full, immutable movement history per spool.
- Archive spools without deleting their history.
- Stable UUIDs for products and spools, including automatic migration of existing databases.
- Printable **60 × 40 mm or 50 × 30 mm QR labels** for individual spools. QR codes open the matching spool in this app.
- **Versioned CSV export and import** with preview, validation, transaction rollback on errors, and idempotent UUID-based matching.
- **Read-only integration API v1** as a foundation for later printer or slicer adapters.

Available in v0.6: session-based authentication and role-based users; local Moonraker/OctoPrint connections with **optional** printer commands, G-code upload and print start; **opt-in** PrusaSlicer CLI for STL slicing with operator-approved profiles; **HMAC-signed vendor-neutral cloud event ingestion**; and explicit multi-material tool-to-spool mapping with atomic accounting. Control and slicing are disabled by default. **Not implemented:** native vendor-specific cloud login/control, SSO/OIDC or automatic slicer tool mapping. Opt-in slicing now uses a separate internal-only worker. See [Print operations and setup](docs/operations.md) and [Security and printer operation](docs/security-and-printers.md).

### Interface language

Select **English** or **Deutsch** in the language selector on the sign-in page or in the application header. The first visit follows the browser's supported language preferences and falls back to English. An explicit choice is saved for that browser and applies after signing out or reloading. Product names, notes, file names, configured currencies and stored API values retain their original meaning. See [language behavior and translation maintenance](docs/interface-languages.md).

**Hardware and interoperability limits:** Native Bambu/Prusa cloud control, complete Spoolman API emulation, unassisted OpenPrintTag decoding, OIDC/SSO and direct USB load-cell drivers are **not implemented**. No real device has been certified. The default one-container deployment works without the optional integrations.

## Quick start (Docker)

For a separate test installation or a prebuilt CI image, see
[Testing Spoolmera](docs/testing.md). Start it with
`python scripts/start_test.py`; it uses its own data volume on port 8766.
The [follow-up review](docs/review-regressions-2026-10-08.md) records confirmed
defects, fixes, executed tests and remaining limitations.

Requires Docker with Compose. The default image builds Angular using Node.js and serves it with FastAPI in a **single runtime container**. An optional PrusaSlicer worker uses a second, isolated container only when explicitly enabled.

```bash
git clone https://github.com/Cenn0/Spoolmera.git
cd Spoolmera
cp .env.example .env
# Generate a random bootstrap secret (32+ characters), then set it in .env:
python -c 'import secrets; print(secrets.token_urlsafe(32))'
docker compose up -d --build
```

Open **http://127.0.0.1:8765** on the machine hosting Docker. First use requires creating the administrator with the server's `SPOOLMERA_BOOTSTRAP_TOKEN` and a password of at least 14 characters. A missing token intentionally prevents account setup.

The database is stored persistently in the Docker volume `spoolmera_data`. To stop the app without removing its data:

```bash
docker compose down
```

Do **not** run `docker compose down -v` unless you intend to remove your saved inventory.

### Configure QR URLs for other devices

By default, QR codes contain `http://127.0.0.1:8765/s/<spool-uuid>`. This works only on the host itself: **127.0.0.1 on a phone is the phone, not your server**.

Set `SPOOLMERA_PUBLIC_BASE_URL` to an origin accessible from the device that scans the label, for example `http://filament.home.example:8765` or `https://filament.example.com`. It must be an HTTP(S) origin without credentials, path, query, or fragment.

Example on a trusted private LAN, after deliberately changing the Compose port binding and ensuring the network is protected:

```yaml
environment:
  SPOOLMERA_PUBLIC_BASE_URL: "http://192.168.1.10:8765"
```

**Security warning:** Application login is implemented, but the Compose service still binds to localhost by default. For access from outside the host, use an HTTPS reverse proxy or protected VPN, set `SPOOLMERA_COOKIE_SECURE=1`, configure `SPOOLMERA_PUBLIC_BASE_URL` as the external origin, and restrict printer egress to explicitly allowlisted IPs. Do not publish unencrypted HTTP login endpoints.

### Print QR labels

1. Add a filament product and create an individual spool.
2. Go to **Spools**, then select **QR label** on the corresponding row or **Print QR label** in its details.
3. Use the browser's print dialog and select a **60 × 40 mm** label (scale 100%, no headers or footers).

The QR code identifies the **physical spool**, not just the filament product. Its URL stays stable through weight changes. The label's printed remaining weight is a snapshot and does not update automatically: print a fresh label if that number matters.

### CSV export and import

Use **Spools → Export CSV** to download an Excel-friendly UTF-8 inventory snapshot. Use **Import CSV** to select a file, preview the changes, then confirm.

- The v1 format includes every product, including products without active spools; it includes only *active* spools.
- Product and spool UUIDs make imports idempotent. An already-known UUID is **skipped**, never overwritten; archived spools are not reactivated.
- The import is **create-only**, atomic, and limited to 2 MiB / 2,500 data rows. Invalid input leaves the database unchanged.
- CSV is **not a complete backup**: historical movements and archived spools are not exported. Keep proper SQLite backups.
- To migrate a current inventory to a fresh instance, export from the old installation and import to the new one. A new initial movement is created for each imported spool, recording its current remaining weight.
- CSV export protects user-entered spreadsheet cells beginning with formula-like characters while preserving round-trippability with this importer.

See [CSV schema and limits](docs/csv-format.md).

### Printer connections, job import, slicing and stock accounting

The **Printers** screen (admin-only configuration) supports **Moonraker/Klipper** and **OctoPrint** controller polling, with optional administrator-only commands and file transfers. The server refuses to connect unless each exact private IP is listed in `SPOOLMERA_PRINTER_ALLOWED_IPS`; public IPs, hostnames, redirects, proxy forwarding and arbitrary remote URLs are rejected.

Place any controller API key in an environment variable such as `SPOOLMERA_PRINTER_TOKEN_WORKSHOP` in the operator's private `.env` file, then enter that **variable name** in the printer form. The key itself is never stored in SQLite. OctoPrint requires an API key; some trusted-LAN Moonraker installations may be reachable without one. Prefer restricted printer credentials and firewall rules.

In **Print jobs**, select a printer and physical spool, then register either the exact filename already on the printer with an estimated gram weight, or import metadata from a local `.gcode`/`.gco`/`.gc` file (up to 16 MiB). **Metadata import** does not store or transmit the file. An administrator can separately enable safe, explicit G-code transfer and manual printer start. Optional isolated PrusaSlicer worker slicing accepts an STL and produces downloadable G-code using a trusted INI profile; slicing is disabled by default. Multi-tool jobs accept explicit material mappings, which are debited atomically if verified. [Detailed operator setup](docs/operations.md).

For Moonraker, enable the job history service. The application polls every 30 seconds by default. Only a unique job-history ID **first observed in progress** and later confirmed completed can automatically debit the estimated grams. The inventory balance and ledger record are committed atomically. All uncertain outcomes require deliberate confirmation or discard; OctoPrint cannot provide an equally authoritative generic completion signal through its current-job endpoint and is always review-only. This is estimated consumption, not physical weighing. A job maps to one or more expressly selected physical spools. Estimates include purge/waste only if the operator enters them.

All inventory routes, printed labels, CSV endpoints, and read-only Integration API v1 endpoints now require login. Roles: **viewer** (read), **editor** (inventory and jobs), **admin** (users and printer configurations). [Security, limitations and implementation details](docs/security-and-printers.md).

## Local development

Python **3.12+** and Angular 22-compatible Node.js (24.15+ recommended). For non-Docker development set `SPOOLMERA_BOOTSTRAP_TOKEN` to a unique, random 24+ character secret before starting FastAPI:

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\Scripts\Activate.ps1
python -m pip install --require-hashes -r requirements-dev.txt
uvicorn app.main:app --reload --host 127.0.0.1 --port 8765
```

Start Angular in a second terminal with a development API proxy:

```bash
cd frontend
npm ci
npm start
```

Open **http://127.0.0.1:4200** for development. Directly opening FastAPI's root without compiled Angular assets displays a build-required response. Docker builds the Angular frontend automatically from the committed npm lockfile.

Type-check and build Angular:

```bash
cd frontend
npm run typecheck
npm test
npm run build
```

Run backend tests:

```bash
python -m pytest -q
```

API documentation: http://127.0.0.1:8765/docs.

### Migrations and backups

Schema v10 adds stock revisions, measurement anchors, reviewed consumption totals, per-printer operation state, batch retry identities and restock targets. Version-gated migrations retain UUIDs, numeric IDs, explicit tool assignments and existing movement history from supported earlier schemas. **Take a consistent SQLite backup before upgrading.** Historical material inconsistencies appear in Operations for deliberate review; migration does not guess which earlier stock movements to correct.

Use the administrator backup download or `python scripts/backup.py /path/to/new-backup.sqlite3 --database /path/to/spoolmera.sqlite3` with access to the mounted data volume. Backups include committed WAL content and enforce size, time and free-space bounds. Restore only with the application stopped, following [the supported recovery commands](docs/operations.md). Restore validates the application schema, retains damaged target bytes and preserves file ownership. Restored sessions and machine tokens are revoked; sign in again and reissue integration tokens. Run one API process per database.

## Architecture

A **modular monolith** is intentional: the single FastAPI service owns authentication, inventory and accounting, with SQLite transactions enforcing consistent stock movements. Angular is delivered as static assets without a Node runtime or CDN. No message broker, Kubernetes cluster or remote database is required.

- `app/api/` contains HTTP endpoints and response contracts; generated Angular API types are checked against the backend schema in CI.
- `app/services/` owns inventory use cases, accounting, durable command intent, polling and lease coordination.
- `app/infrastructure/printers/` normalizes Moonraker/OctoPrint observations and explicit adapter capabilities.
- `app/infrastructure/database/` contains additive, versioned SQLite migrations.
- `app/core/` contains per-route role policies.
- `frontend/src/app/features/` contains lazily loaded Angular pages; inventory refreshes update affected data slices.
- `app/slicer_worker.py` is an **optional** isolated service running with an internal Docker network, non-root user, no printer tokens and no SQLite volume.

The printing path distinguishes registered jobs, observed physical runs, controller commands and inventory movements. Uncertain controller outcomes are **not retried automatically**. Only a confirmed Moonraker history identity observed in progress can automatically debit estimated consumption. For operational limits, state transitions and extension interfaces, read [Architecture](docs/architecture.md), [Operations](docs/operations.md), and [Security](docs/security-and-printers.md).
